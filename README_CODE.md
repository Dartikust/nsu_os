# Как работает код каждой задачи

Здесь разобраны текущие, упрощённые версии программ.
Команды сборки и запуска находятся в [README.md](README.md).

Предполагается обычный учебный ввод: текстовые файлы с короткими строками,
файл не меняется во время работы, номер строки — короткое целое число.
В задаче 4 строка должна помещаться в буфер на 4096 байт.
Поддержка файлов огромных размеров и отдельный отладочный интерфейс не нужны.

## Несколько конструкций C, которые встречаются дальше

- `struct` объединяет несколько полей в одну запись.
- `char *text` — указатель на символ; здесь обычно это адрес начала строки.
- `&value` — адрес переменной. Функция может записать результат по этому адресу.
- `pointer->field` — поле структуры, на которую указывает `pointer`.
- `NULL` — указатель, который ни на какой объект не указывает.
- `sizeof(object)` — размер объекта в байтах.
- `malloc(n)` выделяет `n` байт; `free(pointer)` освобождает их.
- `realloc(pointer, n)` меняет размер выделенного блока и может вернуть другой адрес.
- `static` перед функцией означает, что она используется только внутри этого файла.

Системные вызовы вроде `open()` и `read()` обычно возвращают `-1` при ошибке.
`perror("open")` печатает подпись и описание последней системной ошибки.
У функций библиотеки правила могут отличаться: например, `fopen()` возвращает `NULL`.

`#define _XOPEN_SOURCE 600` перед заголовками открывает объявления нужных
Unix/POSIX-функций в стандартном режиме компиляции, в том числе на Solaris.

## 1. z1.c — опции и атрибуты процесса

### Почему сначала разбираем, а потом выполняем

`getopt()` находит опции слева направо, а задание требует выполнять их
справа налево. Поэтому программа сначала собирает массив, потом проходит
его с конца.

Запись массива:

```c
struct option {
    int name;
    char *argument;
};
```

`name` — буква опции, например `'U'`. `argument` — указатель на её значение,
например строку `"1024"`. У опции без аргумента это поле не используется.

Вызов:

```c
getopt(argc, argv, "ispuU:cC:dvV:")
```

`argc` — число аргументов, `argv` — массив строк аргументов.
`getopt()` возвращает букву следующей найденной опции.
Двоеточия после `U`, `C` и `V` означают, что им нужен аргумент.
Его адрес библиотека помещает в `optarg`.
Когда опций больше нет, возвращается `-1`.

При каждой найденной опции `realloc()` увеличивает массив на одну запись,
после чего сохраняются `opt` и `optarg`. Временный указатель `grown` нужен,
чтобы при ошибке `realloc()` не потерять адрес старого массива.

Когда разбор закончен:

```c
for (int i = count - 1; i >= 0; --i)
    execute(options[i]);
```

В исходнике также запоминается ошибка `execute()` для кода завершения.
Если одна операция не удалась, остальные опции всё равно выполняются.

Например:

```sh
./z1 -u -U1024 -u
```

Порядок действий: правый `-u` печатает исходный лимит, `-U1024` меняет его,
левый `-u` печатает новое значение.

Сохранять нужно аргумент **каждого** появления опции. Одной переменной
`optarg` после цикла недостаточно: она не хранит историю всех значений.

### Как устроена execute()

`switch` выбирает действие по букве опции.

| Ветка | Что происходит |
|---|---|
| `i` | `getuid/geteuid` и `getgid/getegid` возвращают реальные и эффективные идентификаторы |
| `s` | `setpgid(0, 0)` делает текущий процесс лидером группы |
| `p` | `getpid/getppid/getpgrp` возвращают PID, PID родителя и PGID |
| `u` | `ulimit(UL_GETFSIZE)` читает лимит размера обычного файла |
| `U` | `ulimit(UL_SETFSIZE, value)` устанавливает его |
| `c` | `getrlimit(RLIMIT_CORE, &limit)` читает лимиты core-файла |
| `C` | `setrlimit()` записывает новое значение мягкого лимита core |
| `d` | `getcwd()` записывает текущий каталог в `path` |
| `v` | Цикл проходит по `environ` и печатает строки `NAME=value` |
| `V` | `putenv()` добавляет или заменяет строку `NAME=value` в среде |

В `setpgid(0, 0)` первый ноль означает «текущий процесс»,
второй — «использовать его PID как PGID».

В `struct rlimit` два основных поля:

- `rlim_cur` — действующий, мягкий лимит;
- `rlim_max` — жёсткий предел, выше которого обычный процесс поднять мягкий лимит не может.

Для `-C` сначала читается структура, затем меняется только `rlim_cur`,
чтобы сохранить прежний жёсткий предел.
`RLIM_INFINITY` означает отсутствие этого ограничения.

Важно различать единицы: `ulimit()` использует блоки по 512 байт,
а `RLIMIT_CORE` — байты. Особенность Solaris: установка через `ulimit()`
меняет оба лимита размера файла, поэтому уменьшение может запретить
последующее увеличение в том же процессе.

### Зачем нужна number()

Аргумент командной строки — текст. `strtol()` преобразует его в `long`:

```c
*value = strtol(text, &end, 10);
```

`10` — десятичная система. `end` получает адрес первого непрочитанного символа.
Поэтому для `"12abc"` число будет 12, но `*end` окажется `'a'`.
Программа отвергает такую строку, отрицательные значения и переполнение.

Эта проверка оставлена потому, что проверка неудачного значения `-U`
прямо указана в задании. Один `atol("abc")` вернул бы 0,
и программа могла бы ошибочно установить нулевой лимит.

У `ulimit()` отдельно проверяется `errno`: согласно его интерфейсу
возвращаемое `-1` нужно отличать от ошибки по ненулевому `errno`.

### Среда и время жизни памяти

`environ` — массив указателей на строки, заканчивающийся указателем `NULL`.

`putenv()` использует переданную строку, а не обязан делать её копию.
Мы передаём строку из `argv`: она существует до завершения программы,
поэтому этот адрес остаётся действительным.
`free(options)` освобождает только массив записей, не сами строки `argv`.

Изменения среды и лимитов не передаются обратно в запустившую программу оболочку.

## 2. z2.c — время PST

Последовательность короткая:

```c
time_t now = time(NULL);
now -= 8 * 60 * 60;
california = gmtime(&now);
```

`time()` возвращает время в секундах.
`8 * 60 * 60` — восемь часов в секундах.
`gmtime()` раскладывает полученное значение по полям даты и времени в UTC.
После сдвига эти поля соответствуют фиксированному PST = UTC−8.

Если UTC показывает 20:00, после вычитания получится 12:00.
Если UTC показывает 03:00, получится 19:00 предыдущего дня:
день, месяц и год пересчитает библиотека.

Указатель `california` указывает на `struct tm`.
Основные поля:

| Поле | Значение |
|---|---|
| `tm_year` | Число лет после 1900, поэтому прибавляем 1900 |
| `tm_mon` | Месяц от 0 до 11, поэтому прибавляем 1 |
| `tm_mday` | День месяца |
| `tm_hour`, `tm_min`, `tm_sec` | Часы, минуты, секунды |

В `printf()` формат `%02d` дополняет число до двух позиций нулём:
например, 7 превращается в `07`.

Используется `gmtime()`, а не `localtime()`: результат не зависит
от часового пояса удалённой машины.
По условию нужен именно PST. Сезонный переход на PDT здесь не реализуется.

## 3. z3.c — UID и доступ к файлу

### check_file()

Функция выполняет повторяющиеся шаги:

1. Печатает `getuid()` и `geteuid()`.
2. Вызывает `fopen(path, "r+")`.
3. При ошибке печатает `perror(path)`.
4. При успехе сообщает об этом и закрывает файл через `fclose()`.

`"r+"` требует чтения и записи, но не очищает файл.
Ничего не записывается, поэтому содержимое остаётся прежним.

`fflush(stdout)` перед открытием нужен для порядка сообщений:
обычный вывод может быть буферизован, а сообщение `perror()` идёт в stderr.
Без сброса буфера при перенаправлении ошибка могла бы появиться раньше UID.

Приведение к `uintmax_t` и формат `%ju` позволяют напечатать идентификатор
как беззнаковое целое. Это только формат вывода, права доступа от него не меняются.

### main()

Сначала вызывается `check_file()`, затем:

```c
setuid(getuid());
```

В этой программе эффективный UID приводится к реальному UID пользователя,
который её запустил. После этого `check_file()` вызывается повторно.

При запуске владельцем без setuid реальные и эффективные UID уже совпадают.
Поэтому оба открытия файла с правами 600 успешны.

Если одногруппник запускает твою программу с setuid-битом:

- сначала реальный UID принадлежит ему, эффективный — тебе, владельцу программы;
- твой файл с правами 600 открывается;
- после `setuid(getuid())` эффективный UID тоже становится UID одногруппника;
- повторное открытие твоего файла завершается отказом.

Ошибка первого открытия не должна прекращать программу:
по условию надо всё равно выполнить смену UID и повторить попытку.
Именно поэтому результаты `first` и `second` сохраняются отдельно.

`setuid()` проверяется: если смена UID не произошла, продолжать опыт
как будто она произошла было бы неверно.

## 4. z4.c — связный список строк

### Как выглядит узел

```c
struct node {
    char *text;
    struct node *next;
};
```

`text` указывает на отдельную копию строки.
`next` указывает на следующий узел, а у последнего равен `NULL`.

`head` — начало списка. `tail` — последний узел.
В пустом списке оба указателя равны `NULL`.

### Чтение и выделение памяти

`fgets(buffer, sizeof(buffer), stdin)` читает строку в буфер.
Перевод строки `\n` сохраняется, а в конец добавляется нулевой байт `\0`.
Если первый символ `'.'`, ввод прекращается: эта строка в список не попадает.

`strlen(buffer)` считает байты до `\0`, не включая его.
Поэтому под копию нужно:

```c
current->text = malloc(length + 1);
strcpy(current->text, buffer);
```

Если текст занимает 5 байт, памяти требуется 6:
пять под текст и один под нулевой байт.

Сам узел выделяется отдельно через `malloc(sizeof(*current))`.
Два выделения памяти нужны потому, что структура хранит указатель,
а не встроенную строку.

### Добавление в конец

Для нового узла сначала ставим `current->next = NULL`.

Если список пуст, новый узел становится `head`.
Иначе прежний последний узел связывается с новым:

```c
tail->next = current;
tail = current;
```

Первая строка меняет поле старого узла.
Вторая передвигает указатель `tail` на новый последний узел.

Отдельный `tail` позволяет не искать конец списка каждый раз.

### Вывод и освобождение

Для вывода идём от `head`, каждый раз переходя по `next`.
`fputs()` печатает сохранённую строку, в которой обычно уже есть `\n`.

При освобождении сначала запоминается следующий узел,
затем освобождаются текст и сам текущий узел.
Читать `head->next` после `free(head)` было бы обращением к освобождённой памяти.

Фиксированный буфер выбран по подсказке задания: до 4094 байт текста плюс `\n`.
Проверка заполнения нужна, чтобы слишком длинная строка не превратилась
незаметно в несколько узлов. Динамического наращивания строки больше нет.

## 5. z5.c — таблица строк и системные вызовы

### Что хранится в таблице

```c
struct line {
    off_t offset;
    size_t length;
};
```

`offset` — смещение начала строки от начала файла.
`length` — её длина в байтах, включая `\n`, если он есть.

`off_t` — тип файлового смещения.
`size_t` — тип для размеров объектов и блоков памяти.
`ssize_t` — знаковый тип результата `read()`: кроме числа байт он допускает `-1`.

Для текста `ab\ncde\nx` получаем:

| Номер строки | Текст | offset | length |
|---|---|---|---|
| 1 | `ab\n` | 0 | 3 |
| 2 | `cde\n` | 3 | 4 |
| 3 | `x` | 7 | 1 |

Пользователь считает строки с 1, массив — с 0.
Поэтому номеру `number` соответствует `table[number - 1]`.

### add_line()

Функция увеличивает массив через `realloc()`,
записывает смещение и длину, затем увеличивает количество записей.

Параметр `struct line **table` — адрес указателя на массив.
Он нужен, потому что `realloc()` может перенести массив, и функция должна
записать новый адрес в переменную вызывающего кода.
Аналогично `size_t *count` позволяет менять число строк.

### build_table()

`open(path, O_RDONLY)` открывает файл и возвращает целочисленный дескриптор `fd`.
`read(fd, &byte, 1)` читает один байт и двигает текущую позицию файла.

При встрече `\n` вызывается:

```c
position = lseek(fd, 0, SEEK_CUR);
```

`SEEK_CUR` означает отсчёт от текущей позиции, а смещение 0 её не меняет.
Получается позиция сразу после перевода строки.

Начало текущей строки хранится в `start`.
Её длина — `position - start`.
После добавления записи новое начало — `position`.

`read()` возвращает 0 в конце файла.
После цикла проверяется, остались ли байты после последнего перевода строки.
Если да, они образуют последнюю строку без `\n`.
Если файл заканчивается `\n`, лишняя пустая запись не добавляется.

### print_line()

Сначала выделяется `line.length + 1` байт.
Затем:

```c
lseek(fd, line.offset, SEEK_SET);
```

`SEEK_SET` означает отсчёт от начала файла.
Далее читаются ровно `line.length` байт.

Чтение находится в цикле: `read()` может вернуть меньше байт, чем запросили.
`total` хранит, сколько уже прочитано.
Адрес `text + total` указывает, куда дописать следующую порцию.
После чтения добавляется `\0`, чтобы вывести результат через `printf("%s", text)`.

### Цикл запросов и cleanup

`scanf("%ld", &number)` получает номер. Ноль завершает программу.
Проверка границ нужна до обращения к массиву:
`table[-1]` и запись за концом массива не существуют.

В конце вызываются `free(table)` и `close(fd)`.
`goto cleanup` используется только для перехода к общему месту освобождения
ресурсов после ошибки. Это не переход назад и не отдельный алгоритм.

## 6. z6.c — та же таблица с alarm

Построение таблицы и вывод строки такие же, как в задаче 5.
Добавлены обработчик сигнала и функция `read_number()` вместо `scanf()`.

### Установка обработчика

```c
action.sa_handler = on_alarm;
sigemptyset(&action.sa_mask);
action.sa_flags = 0;
sigaction(SIGALRM, &action, NULL);
```

`sigaction()` связывает SIGALRM с функцией `on_alarm()`.
`sa_mask` задаёт дополнительные сигналы для блокировки во время обработчика;
здесь дополнительных сигналов нет.
`sa_flags = 0` оставляет автоматический перезапуск прерванного чтения выключенным.

### read_number()

`alarm(5)` назначает SIGALRM через пять секунд.
Он вызывается один раз на весь ввод номера, а не на каждый символ.

Символы читаются через `read()` до перевода строки, EOF или заполнения буфера.
Затем `alarm(0)` отменяет таймер.
`sscanf()` превращает уже прочитанную строку в число.

Коды результата:

| Код | Значение |
|---|---|
| 1 | Номер прочитан |
| 0 | EOF или нечисловой ввод |
| 2 | Время вышло |
| -1 | Ошибка чтения |

После успешного запроса функция вызывается заново и ставит новый таймер.

### Что делает on_alarm()

```c
expired = 1;
close(STDIN_FILENO);
```

`expired` объявлен как `volatile sig_atomic_t`:
это флаг, который устанавливает обработчик и проверяет обычный код.

`STDIN_FILENO` — дескриптор 0, стандартный ввод.
Его закрытие относится только к текущему процессу:
оболочка, из которой запущена программа, продолжает работать.

Зачем закрывать ввод: если сигнал прервёт `read()`, чтение закончится.
Но сигнал может прийти прямо перед очередным `read()`.
Закрытый дескриптор не позволит этому следующему чтению зависнуть.
После тайм-аута программа всё равно должна печатать файл и завершаться,
поэтому ввод ей больше не нужен.

Внутри обработчика нет `printf()`, выделения памяти или обхода таблицы.
`close()` относится к функциям, допустимым в обработчике сигнала.
Основной код сначала проверяет `expired`, поэтому ожидаемое прерывание
чтения по таймеру не выводится как обычная ошибка.

Получив код 2, `main()` выводит все строки таблицы по порядку
и завершает цикл запросов. Это и даёт всё содержимое файла.

## 7. z7.c — файл через mmap

Таймер и ввод такие же, как в задаче 6.
Меняется способ доступа к содержимому файла.

### fstat() и mmap()

`fstat(fd, &info)` получает сведения об открытом файле.
`info.st_size` — его размер в байтах.

```c
data = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd, 0);
```

Аргументы:

| Аргумент | Смысл |
|---|---|
| `NULL` | Адрес отображения выбирает система |
| `size` | Сколько байт отобразить |
| `PROT_READ` | Разрешить чтение |
| `MAP_PRIVATE` | Частное отображение |
| `fd` | Открытый файл |
| `0` | Начать с начала файла |

После успеха `data[i]` — байт файла со смещением `i`.
`mmap()` возвращает `MAP_FAILED` при ошибке, а не `NULL`.

Пустой файл обрабатывается отдельно: отображение длины 0 создавать нельзя.
Это не дополнительный режим, а необходимый случай для корректного вызова.

### Таблица и вывод

`build_table()` перебирает `data[i]` и ищет `\n`.
Смещение строки — индекс её первого байта; длина считается так же,
как в задаче 5. `read()` и `lseek()` для чтения файла уже не нужны.

Чтобы вывести выбранную строку:

```c
struct line selected = table[number - 1];
fwrite(data + selected.offset, 1, selected.length, stdout);
```

`data + selected.offset` — адрес начала строки.
`fwrite()` выводит указанное количество байт.

Отображение не обязано заканчиваться `\0`, поэтому нельзя просто писать
`printf("%s", data + offset)`: такой вывод мог бы уйти за границу строки
или отображения.

При тайм-ауте выводится вся область `data` длины `size`.
При завершении `munmap(data, size)` удаляет отображение,
`close(fd)` закрывает файл, `free(table)` освобождает таблицу.

В этой задаче `read()` остался только для клавиатуры,
а содержимое файла берётся из отображения.

## Что было убрано и что осталось

Убраны `--table`, проверки предельных размеров и переполнения размеров
выделяемых блоков, проверка типа файла, динамический буфер текущего каталога,
сборка строк произвольной длины в задаче 4 и универсальный разбор ввода
номеров строк. В таймере больше нет `pselect()` и управления масками сигналов.

Оставлены проверки результатов операций, границ номера строки,
неверного `-U` и случая пустого отображения.
Их назначение конкретное: не продолжать опыт после неудачной смены UID,
не обращаться через `NULL`, не читать за границей таблицы
и выполнить прямо указанные в задании проверки.
