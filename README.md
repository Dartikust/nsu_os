# Раздел 1: программы для Solaris

Каждый файл `z1.c` … `z7.c` — самостоятельная программа на C99.
Общих заголовков проекта и дополнительных библиотек нет.
Подробный разбор кода: [README_CODE.md](README_CODE.md).
Сообщения программ на английском, чтобы они читались в удалённом терминале
независимо от его кодировки.

## Перенос и сборка

На Solaris нужны исходники `z1.c` … `z7.c`, `build.sh` и `sample.txt`.
Исполняемые файлы, собранные локально в Linux или Windows, туда не подходят:
собирать нужно на удалённой машине.

Создай на сервере каталог `mkdir -p ~/os-lab`. Затем пример переноса
из локального PowerShell через OpenSSH:

```sh
scp z1.c z2.c z3.c z4.c z5.c z6.c z7.c build.sh sample.txt user@host:os-lab/
```

Замени `user@host` на свои данные. На сервере:

```sh
cd ~/os-lab
sh build.sh
```

Скрипт по умолчанию использует GCC. Если его нет в PATH,
но он установлен в типичном для Solaris 10 каталоге:

```sh
CC=/usr/sfw/bin/gcc sh build.sh
```

Для Oracle Developer Studio:

```sh
CC=cc CFLAGS='-xc99=%all -v' sh build.sh
```

Одну программу можно собрать отдельно:

```sh
gcc -std=c99 -Wall -Wextra -pedantic -o z1 z1.c
```

Для остальных замени номер. Файлы проекта используют переводы строк LF.
Если редактор при переносе поменяет их на CRLF и shell начнёт ругаться
на `\r`, пересохрани `build.sh` с LF.

## 1. Опции и атрибуты процесса

Сначала `getopt()` разбирает аргументы слева направо. Программа сохраняет
пары «опция + её аргумент», затем обходит массив с конца.
Повторные опции сохраняют собственные значения. Двоеточие после буквы
в строке опций означает обязательный аргумент.

| Опция | Действие |
|---|---|
| `-i` | Реальные и эффективные UID/GID |
| `-s` | `setpgid(0, 0)`: группа с PGID, равным PID |
| `-p` | PID, PPID и PGID |
| `-u` | Лимит размера обычного файла, блоки по 512 байт |
| `-U1024` | Установить этот лимит в 1024 блока |
| `-c` | Мягкий лимит core-файла в байтах |
| `-C4096` | Установить мягкий лимит core в 4096 байт |
| `-d` | Текущий рабочий каталог |
| `-v` | Все переменные среды |
| `-VNAME=value` | Добавить/заменить переменную среды процесса |

Аргументы допускается отделять пробелом: `-U 1024`, `-V NAME=value`.

Проверки из условия:

```sh
./z1
./z1 -x
./z1 -i17389
./z1 -i -p -d
./z1 -ipd
./z1 -i-p
./z1 -i - -p
./z1 -Uabc
./z1 -U-1
./z1 -U
```

Без аргументов выводится подсказка, код завершения — 0.
Неизвестная опция, пропущенный аргумент и отдельный `-` считаются ошибками.
При неверных аргументах, например `-i17389`, также печатается `Usage: ...`.
`-i -p` и `-ip` допустимы; `-i-p` недопустимо: внутренний `-`
разбирается как неизвестная опция.
Синтаксические ошибки обнаруживаются до выполнения опций.
Ошибка отдельной операции печатается, остальные сохранённые опции продолжают
выполняться; итоговый код завершения — 1.

Проверить порядок и изменения:

```sh
./z1 -p -s -p
./z1 -u -U1024 -u
./z1 -c -C0 -c
./z1 -v -VLAB_DEMO=hello
./z1 -v -VLAB_DEMO=first -v -VLAB_DEMO=second
```

В первом примере сначала печатается исходная группа, затем процесс становится
лидером группы, затем печатается новая группа: в ней PGID = PID.
В примере с повторными `-V` сначала задаётся `second` и выводится среда,
затем задаётся `first` и снова выводится среда.

`ulimit()` в Solaris при установке меняет **и мягкий, и жёсткий** лимиты
размера файла. Уменьшить можно, а последующее увеличение без привилегий
может завершиться `EPERM`. Неудачное значение вроде `abc` обнаруживается
через `strtol()` — проверяемый аналог подсказанного `atol()`.
В `-C` жёсткий лимит сохраняется; превысить его нельзя.
Фактический core-файл дополнительно ограничивается лимитом размера файла
и настройками системы.

Изменения лимитов и среды относятся к запущенной программе;
родительская оболочка их не наследует.

## 2. PST

```sh
./z2
```

Берём текущее время, вычитаем 8 часов и раскладываем через `gmtime()`.
`gmtime()` использует UTC: часовой пояс удалённой машины не влияет на результат.
Переход через полночь и смену даты обрабатывает библиотека.

Выбран **PST = UTC−8 круглый год**, как в условии и подсказке «20 UTC → 12 PST».
Это не сезонное местное время Калифорнии: летом там используется PDT = UTC−7.

## 3. Реальный и эффективный UID

`getuid()` — пользователь, запустивший программу.
`geteuid()` — идентификатор для обычных проверок доступа.
Setuid-бит позволяет начать выполнение с эффективным UID владельца программы.

`z3` открывает файл в режиме `r+`: нужны права чтения и записи,
содержимое при этом не меняется. После первой попытки вызывается
`setuid(getuid())`, затем снова печатаются UID/EUID и открывается файл.
При ошибке первого открытия вторая часть всё равно выполняется.

На Solaris от своего обычного пользователя:

```sh
mkdir -p setuid-demo
cp z3 setuid-demo/prog
printf 'owner-only data\n' > setuid-demo/data.txt
chmod 750 setuid-demo
chmod 750 setuid-demo/prog
chmod 600 setuid-demo/data.txt
./setuid-demo/prog ./setuid-demo/data.txt
ls -l setuid-demo/prog setuid-demo/data.txt
```

У программы и каталога должна быть группа, в которой состоят одногруппники.
При необходимости используй `chgrp ИМЯ_ОБЩЕЙ_ГРУППЫ` для этих двух объектов.
Для прохода по пути у них должно быть право `x` на всех родительских каталогах.
Если домашний каталог закрыт, используйте подходящий общий учебный каталог.

Одногруппник запускает **твою копию** программы и **твой файл** по абсолютным
путям. Если он скопирует файлы себе, смысл опыта потеряется.
Затем ты устанавливаешь setuid, и он повторяет тот же запуск:

```sh
chmod u+s setuid-demo/prog
ls -l setuid-demo/prog
```

Ожидаемый результат при разных владельцах и обычных правах доступа:

| Кто запускает | До `setuid(getuid())` | После |
|---|---|---|
| Владелец без setuid | UID = EUID = владелец; успех | То же |
| Одногруппник без setuid | UID = EUID = одногруппник; отказ | То же |
| Одногруппник с setuid | UID = одногруппник, EUID = владелец; успех | UID = EUID = одногруппник; отказ |

При отказе открытия программа возвращает 1. В этом опыте отказ — ожидаемое
поведение. Если после `chmod u+s` EUID не меняется, проверь владельца
программы и не смонтирована ли файловая система с `nosuid`.
После опыта сними бит:

```sh
chmod u-s setuid-demo/prog
```

## 4. Список строк

```sh
./z4
```

Введи несколько строк и `.`, либо `.что-угодно` в начале следующей строки.
Затем выводятся сохранённые строки в исходном порядке. EOF тоже завершает ввод.

Узел содержит `char *text` и `struct node *next`. Узлы выделяются через
`malloc()`. `fgets()` читает строку в буфер, затем управляющие символы
преобразуются в ту же видимую запись, что при вводе: ESC становится `^[`.
Под преобразованную строку выделяется память с дополнительным байтом для `\0`.
Стрелка вверх сохраняется как `^[[A`, команды очистки экрана и движения
курсора не выполняются при выводе списка. Обычный перевод строки сохраняется.
Для терминального ввода включается видимое эхо управляющих символов;
при завершении исходные настройки терминала восстанавливаются.
`tail` позволяет добавлять узел в конец без обхода всего списка.
В конце освобождаются и строки, и узлы.

По подсказке задания используется фиксированный буфер на 4096 байт.
Предполагаются строки до 4094 байт текста плюс перевод строки.
Обработки строк произвольной длины нет. STL и `std::string` не используются.

## 5. Таблица смещений строк

```sh
./z5 sample.txt
```

Для файла `first\n\nlast\n` таблица:

| Номер | Смещение | Длина в байтах |
|---|---|---|
| 1 | 0 | 6 |
| 2 | 6 | 1 |
| 3 | 7 | 5 |

Перевод строки включён в длину. UTF-8 учитывается в байтах, а не в символах.
Последняя строка без `\n` тоже попадает в таблицу; после завершающего `\n`
не появляется лишней пустой строки. В пустом файле строк нет.

При построении таблицы `read()` читает по одному байту,
а `lseek(fd, 0, SEEK_CUR)` сообщает позицию сразу после найденного `\n`.
Побайтовое сканирование выбрано для наглядности и коротких учебных файлов.
Для большого файла было бы быстрее читать блоками.

При запросе берём смещение и длину из таблицы, делаем
`lseek(fd, offset, SEEK_SET)` и читаем ровно указанное количество байт.
Под выбранную строку выделяется буфер длины `length + 1`.
Чтение повторяется, пока не получены все `length` байт; затем дописывается `\0`.
Вывод — через `printf("%s", text)`.

Попробуй номера `3`, `1`, `2`, `100`, неверные строки `abc`, `0abc`, затем `0`.
Таблица строится внутри программы, дополнительного режима её печати нет.
Ожидается обычный текстовый файл с короткими строками,
который не изменяется во время работы.
Выход с клавиатуры — только отдельная строка `0`, без пробелов и других символов.
`00`, `+0`, `0abc`, `0 `, пустая строка и неверный текст приводят к новому запросу.
Номер должен целиком занимать строку: `1abc` не считается номером 1.
Слишком длинная строка ввода пропускается целиком.
Закрытие потока ввода обрабатывается как ошибка, а не команда выхода.

## 6. Та же таблица и alarm

```sh
./z6 sample.txt
```

Пять секунд даются **только на первую строку ввода**.
Нужно ввести строку и нажать Enter. После этого таймер отменяется через
`alarm(0)` и больше не включается — даже если первая строка оказалась неверной.
Дальше поведение полностью совпадает с задачей 5: нет ограничения по времени,
неверный ввод повторяет запрос, выход с клавиатуры — только отдельный `0`.
Если первая строка не завершена за пять секунд, печатается весь файл
и программа завершается.

`alarm(5)` вызывает доставку SIGALRM. Обработчик устанавливает
`volatile sig_atomic_t expired` и закрывает стандартный ввод текущего процесса:
после тайм-аута новый ввод больше не нужен. Обычное выполнение замечает флаг,
печатает файл и завершается. Закрытие не позволяет зависнуть на новом `read()`,
если сигнал пришёл прямо перед ним. Печать выполняется вне обработчика.
Вместо `pselect()` и масок сигналов остаются `sigaction()`, `alarm()` и `read()`.
Буфер номера вмещает до 63 байт; более длинный ввод отвергается целиком.

Для проверки запусти программу и ничего не вводи. Отдельно введи номер быстро,
затем подожди больше пяти секунд на следующем запросе: программа продолжит ждать.

## 7. Отображение файла в память

```sh
./z7 sample.txt
```

Сохраняется поведение шестой задачи, включая таймер.
Размер получаем через `fstat()`, файл отображаем через `mmap()` с `PROT_READ`
и `MAP_PRIVATE`. Таблица строится перебором байтов в отображённой области.
Выбор строки — обращение к `data + offset` с известной длиной.

Для доступа к содержимому файла здесь нет `read()`, `lseek()` и `write()`.
Вывод идёт через `fwrite()` из отображённой области; чтение клавиатуры
по-прежнему использует `read()`.
Пустой файл обрабатывается отдельно: `mmap()` с нулевой длиной недопустим.
В конце вызываются `munmap()`, `close()` и `free()`.

## Автоматические проверки

Если установлен Python 3, скопируй также `test.py` и после сборки запусти:

```sh
python3 test.py
```

Скрипт проверяет опции и их порядок, ошибки аргументов, открытие файла
владельцем, фиксированное PST, список, выбор строк, пустой файл,
последнюю строку без `\n`, управляющие символы в терминале,
точное правило выхода по `0`, настоящий первый таймер и отсутствие последующих.
Занимает примерно 11–15 секунд.
Опыты с разными пользователями и setuid нужно отдельно показать на Solaris.

Локальная проверка выполнена в Linux через WSL с GCC.
Она не заменяет окончательную сборку и проверку на Solaris.
